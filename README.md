## 持仓下拉点击修复

“分仓止盈”的持仓列表展开后，列表行与滚动条优先接收鼠标事件，点击不再落到被覆盖的平仓输入框、按钮或 TP 编辑控件。面板恢复标准的置顶与鼠标焦点处理，并单独提高展开下拉框的对象点击优先级；收起后恢复普通面板优先级。鼠标分发继续检查控件可见性，隐藏标签页控件和隐藏列表行不会抢点击。

操作方式不变：展开列表，直接点击对应的“品种 #订单号 买入/卖出”或父组。选择已有持仓只载入其方案；原有未保存草稿保护继续有效。本次没有改变交易、仓位计算或分仓规则。真实鼠标交互需由用户在升级后验收。

## 毫秒级分批开仓

进入 **交易 → 分批开仓**，在“间隔（毫秒）”填写 **100**，再点击“保存并应用分批设置”。可填写 100–3600000 的整数，例如 100、250、500、1000；默认仍为 1000 毫秒。旧版保存的 1 秒会显示为 1000 毫秒，旧设置不会被误读为 1 毫秒。设置在新建父组时冻结，已有组不会因设置修改而加速；建仓过程中不允许保存分批设置。

该数值约束相邻子单**开始发送请求的最短间隔**。EA 使用毫秒定时器推进建仓，没有新报价时也会检查进度；仍须取得上一笔实际成交及有效止损的确认。服务器响应、历史同步和本地处理较慢时，实际间隔会更长，不保证每 100 毫秒成交一单；延迟后不会补发一串积压请求。缩短间隔也不保证消除滑点。

旧父组记录继续按原单位读取；重载或重启后仍只恢复已成交仓位管理，不会自动续开未发送的子单。升级后同一终端请统一使用新版，保留全部持仓日志；旧版不支持新版保存的毫秒设置与新父组记录。

## 直接拖动 TP 价格

在当前品种图表上找到带有持仓编号的 `TP1 / TP2 / …` 水平线，**双击选中，拖到需要的高点或低点后松开**。松开后立即保存到该持仓的止盈方案，不需要手算 R，也不需要再点击页面保存。也可以打开该线的属性，直接填写精确价格。价格自动对齐品种最小跳动单位。

每次只改变所拖目标的价格；该目标的平仓比例和 BE 勾选、其他目标、其他持仓和新仓默认方案保持不变。页面同步显示反算后的 R 与目标价；以后只改比例或 BE，不会因 R 显示精度而改变这个价格。重载后恢复已保存目标。

多笔持仓目标重合时，先在“分仓止盈”页选择对应持仓，该持仓的线会优先响应点击；也可在 MT5 对象列表按持仓编号定位水平线。普通持仓互相独立，**父组仍使用一套共同目标**，拖动父组 TP 会调整该组的共同目标，不拆开各子单管理。

只能修改已经接管、尚未触发的目标。已触发目标、新仓预览、旧版只读记录、退出处理中或暂停管理的目标不能拖动；父组须先结束建仓。目标需保持盈利方向和 TP1→TP2→TP3 的先后顺序，不能重合或越过相邻目标。目标已到价、状态在拖动期间发生变化或保存失败时，会显示原因并恢复已保存位置。

如果页面已有未保存的草稿，图上拖动会保存目标价并保留原草稿，同时提示重新载入，防止旧草稿覆盖图上修改。图上目标属于 EA 的退出计划；最终全平 TP 仍需管理循环向服务器同步，期间可查看“最终TP待同步”状态。

## 父交易组与分批开仓

在 **交易 → 分批开仓** 子页勾选“启用父订单分批开仓”，填写“子单上限(手)”和“间隔（毫秒）”，点击“保存并应用分批设置”。默认上限5手、间隔1000毫秒，分批功能初始关闭；设置保存在当前服务器与账户下，不需F7。主页面的风险金额，例如500，是整组预算，计算结果是计划总手数。只支持对冲账户的即时市价开仓；挂单和净额账户会明确拒绝启用后的分批交易。

父ID是本插件保存的虚拟交易组，不额外向服务器下父订单。真实订单均为子单，带父ID与子序号备注；每子量不超过用户上限、券商品种单笔最大量以及当前剩余总量。每次只处理一笔，上一笔实际成交和止损确认后，满足间隔才发下一笔。时间间隔是最短值，不保证精确按设置间隔成交。

开启后，原计算器不会再因券商单笔最大20手而把整组总量截到20手。每组最多64个子单；每笔发送前仍校验累计手数限制、保证金、点差和风险，并按实际已成交价格到共同止损的预计亏损扣减预算。手续费估算使用主页面佣金设置（单边金额，计算往返），请填入真实费用。滑点和费用会令最终建仓量少于计划量；预算是发送前的控制条件，不保证实际最终亏损恰好不超过该金额。

“最大入场偏离”使用MT5 points，以点击建立父组时的报价为基准，0表示不启用。它用于下一笔发送前检查报价，不是服务器保证成交价格的滑点上限。点差限制继续使用交易页原有的最大点差设置。

交易页显示父ID、已成交与计划手数及状态。“取消剩余开仓”只停止尚未发送的子单，已成交部分保留止损并转入父组管理。明确拒单后停止该组；成交结果尚未确认的请求继续核对，不重复发送，并阻止本终端其他面板继续新开仓，需先核对成交历史。更换账户、重新加载EA或终端重启后不会自动续开未发出的批次；已成交子单和已触发退出继续恢复管理。

在 **分仓止盈** 的持仓下拉中选择“父组”，可以查看整组加权成交价、初始总手数、1R和目标价，修改尚未触发的止盈计划，或按整组当前余仓比例平仓。建仓完成或取消后冻结均价与1R；建仓过程中不允许改整组止盈方案。子单显示父ID，避免同一仓位被父组和单仓RR重复管理。

所有子单使用共同初始SL。整组RR目标以冻结的加权成交价和共同初始SL定义1R；自动百分比按整组初始成交量累计，手动按钮按点击时整组余仓计算。最小手数尾差按整组分配，实际请求量不会为了凑整数擅自扩大比例。父组按整组已实现净损益加浮动净损益监控，达到本组风险金额时响铃并强平余仓；原账户每日保护和单仓保护继续优先执行。

组记录保存在独立的 MQL5/Files/PSRR_Batch/ 账户目录。不要删除日志重新接管正在运行的组；升级时与其他PSRR日志一起保留。

**跟单说明：** 本版只管理源账户中的父组，不创建或配置跟单工具。源端5手按现有0.5倍复制时，接收端通常请求2.5手，但实际取整、成交价、SL/TP修改和部分平仓同步由跟单软件决定。父ID备注是否复制也取决于跟单工具；目标账户没有本插件的源账户父组日志，不会仅凭备注建立同一个父组。源端500预算不保证目标端最终亏损精确250。

## 当前图表下单与全账户持仓管理

将本 EA 挂在需要下单的图表。**下单品种始终是当前图表品种**；主页不再提供品种下拉框、代码输入框或切换按钮。分仓止盈页的持仓下拉框仍可选择整个账户各品种的已有持仓，选择持仓不会改变下单品种。

新仓分仓方案、亏损保护和反向开关继续按同一终端的服务器与账户保存，既有持仓的冻结方案保持各自记录。通过 MT5 自身更换图表品种时，通用风险设置跟随面板，入场、SL/TP 绝对价格及佣金等按品种分别恢复。旧 F7 的 TradeSymbol 与 SymbolChange 字段仅保留用于旧预设兼容，不用于选择下单品种。

定时管理继续覆盖所有品种，不要求当前图表有报价才处理其他品种。已存在且身份匹配的 RR 日志可继续执行，包括原来用其他 Magic 建立的记录；无日志的新仓仅按当前正数 Magic 捕获，首次加载前已有的无日志持仓保持不自动接管。

打开**分仓止盈**，从下拉框选择“品种 #持仓票号 买入/卖出”。可选整个账户的持仓。在“平仓比例”输入框填写数字，例如 25、50 或 12.5（框后显示 %，框内无需输入百分号），再点击**按比例平仓**，只处理这一笔。未选中持仓时按钮显示“先选择持仓”，点击只打开订单列表，不会自动选择或平掉任何仓位。**手动按钮按点击时当前余仓计算；下方自动止盈目标按初始仓位计算。**例如当前余仓 0.16 手，输入 50 表示请求平 0.08 手；100 表示全平。数量向下对齐券商步长，不满足最小平仓量/余仓量则拒绝，不擅自扩大比例。

两次手动25%按余仓连续计算：第一笔完成后，再平剩余75%的25%，理论累计43.75%，余56.25%，并按手数步长取整。进行中的平仓不能重复登记，完成后还需间隔2秒再开始下一笔；快速连点不会排队重复平仓。登记失败的原因会显示在按钮下方和页面底部。

没有 RR 记录的手工单也能手动按比例平仓，但不会凭空生成初始 R 或自动止盈计划。手动减掉的数量会计入已有 RR 方案的累计减仓进度。重复点击、成交结果未知、普通止盈请求未确认时不会重复登记平仓。已登记的手动退出保存到 `MQL5/Files/PSRR_Manual/`，重载后在持仓仍存在时继续；不因重新点击而不断把余量再减同一百分比。

图表目标线只显示当前图表品种，其他品种的目标价可在选中持仓后查看。更换图表或重新加载 EA 前，请先保存需要保留的页面修改。

## 反向开仓先平仓

在**交易**页勾选**反向开仓先平同品种全部反向仓**，默认关闭，勾选后自动保存。开启后，通过本面板开买单会先平该品种所有卖仓，开卖单会先平所有买仓，包含手动单和其他 EA 的反向仓；其他品种与同方向持仓不因该开关被平掉。

点击交易后，先登记旧仓全平任务，等所有相关平仓请求得到确认、旧仓确实消失，再重新检查新单权限、风险、数量和保证金限制并提交。新单手数不超过最初确认的手数；检查未通过就不开新单。因此可能旧仓已平，新单未开，请查看专家日志和提示。持仓总数等组合限制在旧仓平完后重新检查。

**取消后续开仓**只取消后面的新单，已登记的平仓继续完成。修改关键开仓参数、亏损保护介入、切换账户、重新加载 EA 或关闭终端，会取消后续开仓；重新启动不会自动补开反向单。

同品种存在反向挂单时先阻止新单并提示你处理挂单；不会擅自取消这些挂单。若本次是提交新的反向限价/止损挂单，旧反向仓在**提交挂单前**平掉，而非等待该挂单成交。此开关只约束经本面板提交的新单，无法禁止手工或其他 EA 在外部同时交易。

## 在页面填写亏损保护与声音

点击面板顶部的 **亏损保护**，直接填写每笔亏损金额、每日亏损金额，选择单笔范围，勾选成交声音或修改声音文件，然后点击 **保存并应用**。金额以**账户货币**为单位；新安装两个额度默认 **0，表示未启用**，成交声音默认开启。原有止盈方案仍在“分仓止盈”页面设置。

输入框中的修改是草稿，点击保存才生效；切换页面或最小化会保留当前未保存草稿，重载EA只恢复已保存设置。点击“撤销修改”重新读取已经生效的设置。保存后下一次报价或一秒定时检查即按新额度管理现有持仓；**调低额度至当前已发生亏损以内，会触发清仓**。

页面同时显示当天已实现盈亏、全账户当前浮动、每日剩余额度和保护状态。保存的设置按服务器与账户共享，同一终端该账户的多个图表会同步；如果另一图表已经保存新设置，旧草稿不能覆盖它，需重新载入再修改。切换账户会加载新账户的设置，不沿用上一账户的草稿。

首次升级时尚无页面设置记录，会使用原1.40输入参数作为初始值；**页面保存过后，以页面的保存值为准，以后直接在页面更改即可**。旧输入字段保留仅用于首次默认值与旧预设兼容。

| 参数显示名称 | 默认 | 用途 |
|---|---|---|
| 启用整个账户的实际成交提示音 | true | 全账户任何品种实际买卖成交时提示，包括开仓、手动平仓、部分平仓、TP、SL、BE止损退出 |
| 实际成交提示音（Sounds 内 WAV） | ok.wav | 成交声音文件；挂单提交、撤单和只修改SL/TP不算成交 |
| 亏损限额报警音（Sounds 内 WAV） | alert.wav | 达到亏损额度时弹窗并播放此声音 |
| 每笔持仓最大浮亏金额 | 0 | >0 时，所选范围内任何一笔持仓达到额度即报警并请求全部平掉该持仓 |
| 单笔亏损保护范围 | 本 EA 的 Magic，所有品种 | 可改为整个账户所有持仓；匹配 Magic 的旧仓也纳入，无需已有 RR 记录 |
| 整个账户每日最大亏损金额 | 0 | >0 时，按全账户净盈亏判断；触发后先撤所有品种挂单，再请求平掉所有持仓 |
| 显示亏损保护状态 | true | 图表左下显示单笔/每日额度、今日已实现、当前浮动、剩余额度及执行状态 |

**每日口径：今天已实现净盈亏 + 当前全部持仓浮动盈亏 ≤ −每日额度。** 按经纪商服务器日期，从 00:00 开始统计；盈利会抵扣亏损。例如今日净亏损 2500、当前净浮亏 400，设置 2900 时触发。若同时有另一仓浮盈100，则当前净浮亏为300，尚未触发。每日额度不是从日内最高净值计算的回撤额度。

已实现部分包含当日买卖成交的盈利、已记账隔夜费、佣金和成交费用，以及单独记账的佣金、附加收费、利息、股息和税费；充值、提现、信用、奖励和余额修正不计入。当前浮动包含持仓盈利与已累计隔夜费；隔夜未平仓按**整笔当前浮动盈亏**计算，不是只计算今天的价格变化。券商将交易费用记为充值/余额修正等非标准类型时，需对照账户历史确认口径。

**单笔口径：该持仓当前浮动盈亏 + 累计隔夜费。** 不含此前已实现的部分平仓结果、已扣开仓佣金，也不预估退出手续费。净额账户中“每笔”指该品种合并后的整个净持仓，不能分离成各次入场。默认单笔保护仅匹配本 EA 当前 Magic；每日保护始终包括手动交易和其他 EA，所有品种，不受 Magic 限制。

触发后立即保存退出意图，价格回升、修改额度或重启 EA 不会撤销已触发的清仓。每日触发会保持锁定至下一个服务器日：当天本 EA 拒绝新开仓；手动或其他 EA 仍可能开仓，本 EA 检测到后继续撤单/平仓。若跨日仍有未完成的清仓，会先完成清仓再解除旧日锁定；新一天若仍达到新日额度，可再次触发。单笔触发仅清该仓，不设置全天禁开仓。

亏损保护独立于“启用分仓止盈”；关闭 RR 功能不会关闭已设置的金额保护。将金额设为0只停止新增触发，**不会取消已经保存的退出任务或当天锁定**。同一终端、同一账户共享页面保存的设置；“本EA的Magic”按每个运行实例的当前Magic判断，多个实例可各自覆盖其Magic对应持仓。不要在多个独立终端同时管理同一账户。

需要终端联网、EA 持续运行并允许算法交易。失去权限时会保存触发、报警并显示等待，恢复后重试。超时或成交结果不确定时先核对历史，不盲目重复平仓；无法确认的请求会保持等待并显示原因，需要人工核对。额度是**发送市价平仓的触发条件**，不是保证最终亏损恰好等于设定额；跳空、滑点、延迟和退出费用可能使最终损失更大。

声音依赖 MT5 的 Sounds 目录和系统音量；多个同时成交会合并成一次提示，多个图表不会对同一成交反复播放。风险声音在短时间内优先于随后的强平成交声。页面关闭成交提示后，成功成交不会再从原版提交音绕过开关；亏损报警独立保留。原版 `DisableTradingSounds` 仍控制提交失败音。声音无法播放时会写入“专家”日志；MT5 策略测试器不验证实际音频播放。

保护记录保存在 `MQL5/Files/PSRR_Guard/<服务器标识_账户>/`，与原来的分仓记录分开；`settings.bin` 保存页面设置，`daily.bin` 及持仓/挂单记录保存已触发任务。升级/迁移时保留此目录，不删除文件绕过退出任务。配置读取失败会阻止新开仓及按未确认配置产生新触发，已保存的退出任务继续执行；页面显示错误。保存结果不明确时，重新载入核对最终生效值。

## 在页面设置止盈

点击面板顶部的 **分仓止盈**。默认是 2R 平 50% 并 BE、5R 平剩余 50%。

1. 点击“添加目标”，填写目标 R 和平仓百分比；可删除不需要的行。每页显示 5 行，多于 5 行时翻页编辑。
2. 在希望上保护的目标行勾选 **BE**。允许多行勾选；价格达到任意勾选目标就请求将止损移至开仓价（加输入参数中的保本偏移）。若止损已更有利，不会移回较差位置。
3. 只想上保护、不想减仓时，设置 **0% 并勾选 BE**。
4. R 必须为正数并严格递增，平仓百分比合计 **不能超过 100%**。不足 100% 时保留余仓；合计 100% 时最后一行执行剩余全平，处理手数取整后的余量。只有 BE 的 0% 方案也可以保存。
5. 在 **新仓方案** 模式点击 **保存新仓方案**，仅用于后续新仓。有本 EA 的未成交订单或尚未完成记录的新仓时，需要先等待订单处理完成再保存。未保存草稿不影响执行。

## 保留余仓继续持有

例如初始 **0.32 手**：2R 平 **50%（0.16 手）并 BE**，5R 再平 **25%（0.08 手）**，合计 75%，剩下 **25%（0.08 手）** 继续持有。这里的 25% 是初始仓位的 25%，不是当时余仓的 25%。

在分仓止盈页把第二行从 50 改成 25，点击 **应用到该持仓**。页面会显示“已安排 75% / 保留 25%”。如果第一行已触发，它仍然锁定，原来的减仓和 BE 进度不会重置。

**保留余仓模式不设置服务器全平 TP。** 修改已有持仓时会请求取消旧 TP，同时保留已有止损和已经触发的 BE。页面显示“旧 TP 待取消”时，旧服务器 TP 仍可能生效；显示“全平 TP 已取消”才表示实际 TP 为 0。新单从一开始便不带服务器全平 TP，中间目标由 EA 市价减仓。

所有已设目标执行完后，EA 不会继续平余仓。你可以使用 MT5 的平仓操作手动减仓/全平，或继续添加更高 R 的目标再应用。也可以删除全部尚未触发目标，只保留已触发记录和余仓；已触发记录不能修改或删除。EA 按累计初始比例扣除手动已减数量，不补回仓位。

BE 仍按勾选目标触发；没有勾选或尚未触发 BE 的方案，余仓保留原有 SL，并不会自动变成保本。保留余仓模式运行时 EA 会保持服务器 TP 为空；希望恢复自动全平时，可添加未来目标使总比例达到 100%。

## 在持仓过程中修改

1. 打开 **分仓止盈**，从持仓下拉框选择相应品种与持仓编号。
2. 页面显示该仓位的真实成交价、冻结的 1R 和剩余手数。修改尚未触发的目标 R、初始仓位百分比、BE，也可以增加或删除未触发目标。每行显示目标价。
3. 点击 **应用到该持仓** 才保存；只修改当前选中的仓位，不会改变其他仓位或新仓默认方案。图表线显示已保存方案，编辑框中的目标价是草稿预览。
4. 已触发的行锁定，不可以修改或删除；原来的初始手数、1R、减仓进度和已经触发的 BE 都保留。例如 2R 已平 50% 后，后面的 5R/50% 可改为 6R/50%，不会再平一次前 50%。
5. 编辑期间若已触发新目标或其他图表已修改方案，保存会拒绝旧草稿，需要重新载入。平仓等待确认、管理暂停或已触发减仓尚未完成时也暂不能保存。
6. 新目标必须位于当前可平仓报价的盈利方向前方至少一个最小跳动，防止保存后立即补平已经越过的目标。手动减仓计入累计，后续减仓须满足券商最小手数。

全平方案的最终 TP 保存后由管理循环向服务器同步，保留余仓方案则同步取消该 TP。页面和图线会区分 **TP 待同步**、**旧 TP 待取消** 与实际已生效状态；算法交易关闭、连接中断或券商拒绝期间，旧服务器 TP 仍可能有效。没有收到服务器确认前，不应把草稿或新目标线当作已修改成功的服务器订单。

RR 1.10 建立的多目标持仓记录可以直接编辑；RR 1.01 的旧两阶段记录仅支持显示，继续按旧执行语义管理。没有 RR 记录的旧仓不会通过编辑页面自动接管。

## 图表上的目标线

每条持仓目标线标注类似 `#158809575 | TP1 2R | 4326.38 | 平 50% + BE`。已触发目标保留并显示灰色及“已触发”；触发表示条件已经锁定，不代表平仓和 BE 两个请求均已成功。有管理中的仓位时，目标按真实成交价和原始止损距离计算，不跟随左侧新单预览价。

没有可显示的 RR 持仓时显示“新仓预览”；它随计算器变化，仍仅供预览。超出当前图表价格范围的目标保留水平线，并在边缘标出“图外”和价格。持仓的可编辑目标可双击后拖动，也可在分仓止盈页继续编辑 R、比例和 BE。持仓关闭后对应线自动清除，卸载 EA 只清除本模块的目标标记，不删除手动画线。

到价判断与图线采用同一个合法最小跳动价。多单看 Bid、空单看 Ask；RR 1.20 修正了恰好到达目标价格时因浮点误差延后一跳的问题。

例如：

| 目标 | R 倍数 | 平仓比例 | BE |
|---|---:|---:|---|
| 1 | 1 | 0% | 勾选：只上保护 |
| 2 | 2 | 50% | 不勾选 |
| 3 | 3 | 25% | 可勾选 |
| 4 | 5 | 25% | 不勾选 |

**自动目标的百分比按初始仓位计算**；页面手动平仓按钮则按点击时余仓计算。新仓默认方案按服务器与账户共用，正常重启、切换品种和周期后恢复。升级时优先读取已有共用方案；尚无共用记录时迁移当前图表品种的旧方案。其他旧品种默认方案不自动合并，既有持仓方案保持各自记录。

## 首次加载的默认规则

以下四个目标相关输入仅在本图表尚无已保存方案时生成初始两行。已有保存方案时，请在“分仓止盈”页面编辑。

| 设置 | 默认值 | 含义 |
|---|---:|---|
| 启用分仓止盈 / `RR_Enable` | true | 使用本扩展管理退出 |
| 第一目标 / `RR_FirstTarget` | 2.0 | 到初始风险的 2 倍时减仓 |
| 平仓百分比 / `RR_ClosePercent` | 50.0 | 平掉**初始仓位**的 50%，不是每次平掉剩余的一半 |
| 最终目标 / `RR_FinalTarget` | 5.0 | 到 5R 平掉全部剩余仓位 |
| 第一目标保本 / `RR_MoveToBE` | true | 新方案第一目标到价即请求 BE；与平仓请求分别确认 |
| 保本额外点数 / `RR_BEOffsetPoints` | 0 | 0 = 实际开仓价；正数向盈利方向偏移，单位为该品种的 point |
| 平仓偏差 / `RR_DeviationPoints` | 20 | 市价平仓允许偏差，单位 point，实际处理取决于券商执行模式 |

`1R = |实际开仓价 − 初始止损价|`。成交后记录下来，不随止损移至 BE 或调整图表线而改变。

例如，多单开仓 3000、初始止损 2990、初始仓位 0.10 手：

1. 1R = 10 个价格单位。
2. Bid 到 3020：请求平 0.05 手，并请求把止损移到 3000；两项以交易服务器确认结果为准。
3. Bid 到 3050：平掉剩余 0.05 手。
4. 如果完成第 2 步后先回到 BE，则剩余仓位在保本止损退出，不再等待 5R。

空单方向相反，使用可实际平仓的 Ask 判断目标。上述合计 100% 的默认方案若直接跳到最终目标，则直接全平；保留余仓方案跳过多个目标时只补足已触发目标的累计比例。

这里的 R 是价格距离倍数。BE 默认是开仓价格，不包含手续费、隔夜费和成交滑点，因此不等于扣除成本后的净收益为零。两个目标均成交时，默认组合约为 **3.5R**，未扣成本。

## 安装和使用

1. 在 MT5 中选择“文件 → 打开数据文件夹”，进入 `MQL5\Experts`。
2. 新建 `PositionSizerRR` 文件夹，将本包 `mt5` 内文件放入。已有编译版时只放 `Position Sizer RR.ex5` 也可运行，图标已嵌入。
3. 在导航器刷新“EA 交易”，把 **Position Sizer RR** 加载到你准备交易的品种图表。
4. 在面板 **分仓止盈** 页添加和保存各目标；首次加载默认 2R/50%/BE、5R/50%。先用模拟账户验证券商执行情况。
5. 主页的止盈数量设为 **1**，交易页原有“Break-Even / 保本”和“Trailing Stop / 移动止损”均设为 **0**；保持应用 SL 和 TP。多个目标统一在 **分仓止盈** 页管理。
6. 默认专用 Magic Number 为 **2026092201**。不要与其他 EA 共用；持仓期间保持 Magic 和交易品种不变。
7. 正常在面板选择多空、拖动初始止损、设置风险比例或金额，确认仓位，再按原来的交易按钮下单。主页显示最后计划目标的预览价；保留余仓方案标为“末目标”，该价格不作为服务器全平 TP 提交。
8. 保持 MT5、图表上的 EA 和“算法交易”运行。第一阶段减仓与 BE 需要终端在线；成功提交到服务器的 SL 和最终 TP 在终端关闭后仍由服务器执行。

RR 模式在当前图表品种下单，同时管理账户内已有 RR 记录的各品种持仓；主页不提供品种切换。**新仓成交并完成首次记录时冻结方案、初始风险、BE 偏移**；已记录仓位继续使用其保存参数。存在本 EA 未成交订单或未捕获新仓时，页面禁止保存新方案。平仓偏差使用当前输入值。

面板设置独立保存到 `MQL5/Files/PSRR_Settings/`，默认图表对象前缀为 `PSRR_`，与原版设置隔离。

面板的“收益”和风险回报字段仍沿用原版**全仓在最终 TP 退出**的估算；例如会显示接近 5R，而不是分仓组合的 3.5R。实际分仓规则以 RR 参数为准。

## 执行细节

- **分仓止盈**管理所有品种中当前面板正数 Magic 匹配的新仓，以及已有有效 RR 记录的仓位。首次加载时已有、没有 RR 记录的仓位不会自动接管分仓方案。金额亏损保护按上文范围执行，可以包含这些旧仓。
- 对冲账户按具体持仓票号减仓/改止损，可分别管理多张持仓。
- 净额/交易所账户每个品种只允许一笔独立入场。在该品种已有任何持仓或挂单时，RR 模式会阻止新入场；开启反向开关时，可先将全部反向仓平完，再按独立新仓入场。不要让其他策略同时操作同品种。检测到外部加仓、反转或均价变化后，暂停该仓位管理并记录日志；已有服务器 SL/TP 不会因此自动删除。
- 挂单实际成交后才建立 R 基准；同一入场单分次成交时，等待入场订单结束后确认实际总手数。
- 中间目标按累计百分比计算，再按券商步长向下取整。例如 0.03 手的 50%，在步长 0.01 时实际平 0.01 手，剩 0.02 手。下单前检查每一阶段的平仓量和余仓量，无法满足最小手数时拒绝下单。
- 已有仓位若因外部变化无法完成规定分仓，不擅自扩大减仓量，写日志并等待后续目标；已触发的 BE 独立重试。
- 已手动减少的仓位计入累计减仓量。达到第一目标时，只补足还需要减少的数量。
- BE 只会改善止损，不会把已移动到更有利价格的止损拉回开仓价。券商止损距离或冻结区不允许修改时继续重试；此期间旧止损仍有效，BE 尚未生效。
- 合计 100% 时最终服务器 TP 以实际成交价和初始止损为基准校正到合法 tick；合计不足 100% 时全部目标由 EA 按比例市价执行并保留余仓。实际成交价格可能有滑点。
- 本版本的市价平仓使用 FOK 或 IOC；品种若两者均不支持则停止自动市价分仓并记录日志。最终服务器 TP/SL 的执行不依赖此市价平仓模式。

## 重启恢复与异常

每笔仓位的初始风险、初始手数、冻结参数和阶段写入终端数据目录的 `MQL5\Files\PS_RR\<服务器标识_账户>\<持仓标识>.bin`。

正常重启或重新加载后，读取记录并核对成交历史；已经完成的第一阶段不会重复平仓。关闭前尚未成功设置 BE 的，会继续尝试设置。换电脑/换终端时，除 EA 文件外，还需迁移对应 `PS_RR` 状态目录。

为防止超时后重复平仓，程序先保存交易意图，再发出请求。若服务器回复不确定、成交记录未同步或记录文件损坏，程序会暂停该仓位的后续管理并在“专家”日志提示，等待确认或人工核对。**不能保证所有断线异常都会自动恢复。**不要通过删除状态文件强行重置；先核对终端持仓、交易历史和日志。不要在多个不同 MT5 终端上同时运行本 EA 管理同一账户的同一仓位。

原版 EA 不应同时管理同一批仓位；否则原版 BE/移动止损或人工操作可能与本扩展冲突。

升级前已由 RR 1.01 记录的仓位继续使用旧两阶段规则和旧日志格式（减仓确认后设 BE）。保存新仓默认方案不会覆盖已有仓位；编辑 RR 1.10/1.20 持仓需要明确选择该仓位并点击“应用到该持仓”。
