# MT5 模拟账户验收

以下是**待执行的验收场景**，不代表已经连接 MT5 或下过任何交易。先完成 MetaEditor 编译，再在模拟账户或能覆盖对应成交行为的策略测试器中执行。净额与对冲账户都要覆盖；记录账户模式、品种的最小手数/手数步进/tick size、输入参数、成交历史和 Experts 日志。

数学回归测试使用 Node 执行 `tests/rr_core.test.mjs`。它读取 `mt5/RRCore.mqh` 的真实函数体，仅适配 MQL 的基础数学函数，不能替代 MetaEditor 编译、经纪商成交和重启验收。

状态回归测试使用 Node 执行 `tests/rr_manager.test.mjs`。它执行实际管理器的状态推进、平仓确认和止损修改函数，模拟持仓、历史、持久化和交易接口；覆盖部分成交补足、重启状态、未知结果防重发、BE 重试及净额变更暂停，不验证实际交易服务器或文件 IO。

## 基本设置

- 只使用专门用于测试的模拟账户；初始仓位设置有效止损，仓位魔术号与 EA 的管理范围一致。
- 在“分仓止盈”页面保存默认 2R/50%/BE、5R/50% 方案，BE 偏移为 0。RR 1.10 新仓到目标即请求 BE，独立于减仓确认；RR 1.01 已有仓位仍按旧规则处理。
- 为每个案例记录初始成交价、初始止损、初始手数和初始 1R。1R 应固定为入场价与初始止损之间的距离，不能因 BE 修改后重新计算。
- 买单用 Bid、卖单用 Ask 判断可平仓价格；实际成交受报价、滑点和交易规则影响。
- 用原 Position Sizer 开仓时，确认其原有多 TP、BE 和跟踪止损设置不会与本功能同时控制同一仓位。

## 必须通过的场景

| 场景 | 操作 | 验收标准 |
| --- | --- | --- |
| 买单 2R / 5R | 用可精确对半的手数开买单；依次触达 1.99R、2R、5R | 1.99R 不减仓；2R 仅减初始手数的 50%，余仓 SL 调至入场价；余仓在 5R 清零。入场价格随滑点按实际成交记录核验。 |
| 卖单价差 | 让 Bid 先低于 2R 目标但 Ask 仍高于目标，之后 Ask 触达 2R | Bid 单独触达时不减仓，Ask 到达后才减仓；最终 5R 也按卖单可成交价验证。 |
| 直接跳过 5R | 一个报价跳空从不足 2R 到超过 5R | 优先结束整仓，最终无余仓；不得为了第一阶段再开出反向仓位。若经纪商已执行最终 TP，不得再对消失仓位发平仓请求。 |
| 第一阶段只做一次 | 首次 2R 减仓后，价格多次上穿/下穿 2R | 不再从余仓重复减半。成交历史中的累计第一阶段减仓量不超过目标数量。 |
| 第一阶段前重启 | EA 已记录初始风险后，移除并重新加载 EA，或正常重启终端 | 使用原有初始风险和初始手数继续管理；不能因为后续 SL 改动而把 1R 变成新的距离。 |
| 第一阶段后重启 | 2R 减仓和 BE 完成后重启终端 | 无重复减仓；剩余仓位继续以原始 1R 的 5R 为目标。 |
| BE 被拒后重试 | 通过较大的 stops/freeze 限制或测试器故障模拟，让减仓成功但 BE 修改暂时失败 | 日志说明修改失败；后续在规则允许时重试 BE；重试过程中不得再次减仓。BE 最终成功前仓位仍受实际已生效的 SL 约束。 |
| BE 失败期间重启 | 在上一案例减仓成功、BE 尚未成功时重启 | 恢复“已减仓、待 BE”状态；仅重试 BE，不再次减仓。 |
| 最小手数 | 以经纪商最小手数尝试两阶段50%方案开仓 | 下单前拒绝无法合法拆分的手数；若捕获后受外部变化影响无法分仓，不能擅自全平，已命中的BE仍独立执行。 |
| 奇数步进 | 最小手数和步进均为 0.01 时，以 0.03 手开仓 | 50% 向下取到 0.01 手减仓，保留 0.02 手；不发送 0.015 手请求。日志/界面不可声称精确减掉 50%。 |
| 余仓不足最小量 | 设定较高减仓比例，使按比例减仓后的余仓低于最小手数 | 不发送非法量，不为了满足第一目标而擅自全平；最终目标仍按设计生效。 |
| 手动提前部分平仓 | 第一目标前手动减掉小于或等于目标数量 | 已减数量计入初始仓位的累计减仓目标；达到第一目标时只补足差额，不对“当前余仓”重新减半。若已达到目标数量，应核验阶段状态和 BE 行为。 |
| 魔术号隔离 | 同一品种同时开两个不同 magic 的仓位；另有手工单 | 只管理明确纳入范围的仓位，其他仓位的 SL、TP 和手数均不改变。对冲账户还要验证同品种不同 ticket 的独立性。 |
| 品种隔离 | 在两个品种开仓，按配置仅管理当前品种 | 另一个品种的仓位不被处理。若启用全品种，分别使用各品种 tick、point、最小量和步进。 |
| 净额账户加仓 | 初始风险已记录后，对同方向净仓位加仓 | 不把新仓位混入旧的 50% 目标；应明确检测数量/均价变化并停止旧计划或按文档要求重新建立计划，不能静默沿用失真的风险。核验日志。 |
| 净额账户反转 | 对原净仓位发足够大的反向单导致方向反转 | 旧的入场价、风险、第一阶段状态不应用到反转后的仓位；不能因旧状态立即错误平掉新方向仓位。 |
| 净额账户 magic 混用 | 其他 EA 或手工交易合并进同一品种净仓位 | 核验日志和文档中净额隔离的限制，不得把 magic 过滤误认为能分离同一净仓位的不同交易来源。 |
| 原面板多 TP 冲突 | 在原面板启用多个 TP，尝试同时启用 RR 管理 | 按实现的防冲突规则明确拒绝不兼容配置或要求使用单 TP；不得悄悄让原多个 TP 和 RR 计划共同多次减仓。 |
| 原面板 BE / trailing 冲突 | 设置原面板 BE 或跟踪止损，再启用 RR 管理 | 按文档明确避免两个止损控制器冲突；已经更有利的 SL 不得被 RR 的 BE 操作移回较差位置。 |
| 成交部分完成 | 在可模拟部分成交的交易环境中，第一阶段请求仅成交一部分 | 以实际剩余量为准，仅补足目标减仓差额，不重复请求原始目标量；最终全平也应处理尚存余仓。 |
| 无有效初始止损 | 开无 SL 仓位，或 SL 已在盈利侧但缺少已保存的初始计划 | 明确不接管无法推导初始风险的仓位，不猜测初始 1R；日志可追踪原因。 |
| tick 与 point 不同 | 选择 tick size 大于 point 的品种或自定义测试品种 | 目标价和 BE 价均在有效 tick 上；目标价向盈利方向取整，不早于目标 R；BE 不因舍入落在亏损侧。 |
| 更有利的止损 | 第一阶段前手动将 SL 调至比 BE 更有利的位置 | RR 管理不把 SL 改回较差的 BE 价格；最终目标仍使用原始风险。 |
| 交易暂停 / 断连 | 在触达目标时禁用算法交易或模拟断连，之后恢复 | 不伪报成交成功；恢复后按当前仓位和持久状态继续，最终不重复减仓或误开反向仓位。如已发送请求但结果无法核实，应暂停并明确日志，人工核验成交，不应擅自重发。 |
| 删除后重新开仓 | 完全平掉一个仓位，再在相同品种以相同 magic 新开仓 | 新仓位建立独立状态，旧仓位“第一阶段已完成”的标记不能污染新仓位。 |

## RR 1.10 多目标与页面

| 场景 | 验收标准 |
|---|---|
| 添加、删除、分页 | 添加至少6行；翻页、修改、回上一页，数据不丢失；删除后编号和页数正确；最多20行 |
| BE独立选择 | 任意行能勾选/取消BE；保存后重新加载仍保持；0%且BE有效，0%未选BE拒绝保存 |
| 非法方案 | 负数、文字、多个小数点、重复/倒序R、合计非100%、非末行已100%均不能覆盖旧方案 |
| 未保存编辑 | 修改行后直接在主选项页计算，最终TP仍按上次保存方案；点击保存后才更新 |
| 三阶段执行 | 初始1手：2R平0.50、3R平0.25、5R平余仓0.25；每阶段只补足初始仓位累计目标 |
| 独立保护节点 | 1R/0%/BE、2R/50%、5R/50%：1R只改SL不减仓，2R首次减仓 |
| 多节点跳价 | 一次越过2R/50%和3R/25%且第二行BE：累计平0.75并上保护；不逐次按剩余仓位计算 |
| 平仓待确认仍上BE | 第一笔部分平仓尚未确认时价格触及后续BE节点：锁存BE并尝试保护，不重复发平仓单 |
| 触发后回落/重启 | 已触发目标持久化；回落或重载后仅完成尚缺的累计减仓和BE，无重复平仓 |
| 方案冻结 | 已捕获仓位使用旧计划；保存新方案后新仓使用新计划；同品种同Magic有挂单或未捕获新仓时禁止保存 |
| 旧日志升级 | 使用RR1.01已记录的stage0/1/2/3及pending记录；RR1.10仍用旧结构读写，保留原BE时点、sequence和请求确认 |

## RR 1.20 目标线与持仓修改（本轮交由用户自行验收）

| 场景 | 验收标准 |
|---|---|
| 持仓真实目标线 | 每笔已有 RR 记录的持仓都显示编号、TP序号、R、价格、初始平仓比例、BE；真实目标不随新单计算器的入场价变化 |
| 精确空单边界 | 示例成交4341.74、原始SL4349.42：2R线4326.38，5R线4303.34；Ask恰好4326.38即锁存2R，不再额外等待下一跳 |
| 图外与相邻目标 | 目标不在当前价格范围时有图外价格提示；相邻目标标签尽量错开；缩放/切周期后仍对齐，原有手动画线不受影响 |
| 只保存草稿 | 切到某笔持仓后修改未来R/比例/BE，未点击应用前旧目标线和实际方案保持不变；撤销可恢复已保存值 |
| 修改现仓 | 原2R/50%/BE、5R/50%，第一阶段完成后把末目标改6R/50%；保存后余仓最终TP变化，第一行保持锁定，不重复平半仓 |
| 新增目标 | 在尚未触发阶段间加入一行，重新分配未触发部分的百分比，使总和100%；保存后新线出现，只影响所选持仓 |
| 选仓隔离 | 两笔相同品种和Magic的仓位分别选择；修改A不影响B、新仓默认方案或其他Magic；带未保存修改时切换应提示先保存或撤销 |
| 持仓变化时的旧草稿 | 输入期间另一个TP触发，或其他图表保存方案；旧草稿不能覆盖最新进度，重新载入后已触发行锁定 |
| 请求等待与失败 | 平仓待确认、管理暂停、历史不完整、已触发减仓未完成时禁止应用；不会重置pending、stage或BE意图 |
| 目标太近/已越过 | 新目标在当前可平仓报价后方或不足一个tick时拒绝保存；原目标刚刚到价也不能被编辑抹除 |
| 服务器同步状态 | 修改最终R后先显示待同步；实际Position TP达到新价才显示已同步。交易关闭或券商拒绝不能被标成成功，原服务器TP仍可能生效 |
| 保存后重载 | 保存某笔持仓方案后重载EA；新目标、原始1R、已触发阶段、未完成BE、累计减仓进度一致，不重复退出 |
| 旧版兼容与平仓清理 | RR1.01持仓只读；RR1.10持仓可编辑；无日志持仓不自动接管；持仓退出后只清除它的目标线 |

本版本未在用户终端执行升级后的界面操作、开仓、平仓或修改 SL/TP。原生编译与内存边界测试结果见 VALIDATION.md。
